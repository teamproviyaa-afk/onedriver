# Implementation decisions and documented conflicts

| # | Topic | Decision |
|---|---|---|
| 1 | Repository state | Both `onedriver` and `onelatur2.0` were empty; there was no existing OL-ui, API client, Supabase setup or env system to reuse. The app was scaffolded with `create-expo-app` (SDK 57 default template, `src/app` router root) and everything else built new. |
| 2 | Figma assets | The sandbox blocks figma.com downloads. Raster illustrations were captured at native resolution through the Figma MCP screenshot channel (`assets/figma/*.png`). Icons are Lucide glyphs in the design → `lucide-react-native` (vector). iOS status-bar glyphs are never rendered by the app. |
| 3 | Tab bar | Figma home frames show HOME / JOBS / EARNINGS / PROFILE while every other frame shows TASKS / EARNINGS / ALERTS / PROFILE; the PDF says "Tasks · Earnings · Alerts · Profile, plus Home". Implemented one 5-tab bar (HOME, TASKS, EARNINGS, ALERTS, PROFILE) in the majority visual style (lime active pill). |
| 4 | `picked_up` step | The PDF step body omits `picked_up` although the state exists. Added it to `StepTarget` so "Proceed to delivery" is an explicit transition. |
| 5 | Earnings breakdown card | Figma delivery-detail uses near-black text on a black card; rendered with white/lime text for legibility. |
| 6 | Cash screen | No Figma frame exists for cash-in-hand / deposit; built in the same visual language (spec requires it). |
| 7 | Support screen | Referenced by help buttons but not designed; built minimally. |
| 8 | Customer-unavailable wait | Spec: "mandatory wait timer"; value not fixed → 5:00 (server-configurable via `waitSeconds`). |
| 9 | Order-not-ready threshold | 10 minutes free, then wait compensation at the rule's per-minute rate (configuration-driven, demo ₹2/min). |
| 10 | Demo GPS | In `local_demo` a route simulator drives the rider to pickup/drop so testers can complete the journey anywhere; device GPS can be enabled from the DEV panel. |
| 11 | Expo Go limits | Android foreground-service location and remote push need a development build; the app degrades to foreground GPS + local notifications in Expo Go. |
| 12 | V2 / coming soon | Taxi Partner, rental marketplace, combined delivery, chat, masked numbers → "Coming soon" sheets, never operational. Withdraw earnings was in this list (spec R11: "needs RazorpayX/Cashfree Payouts"); Cashfree was then chosen, so it is operational — see #19. |
| 13 | Supabase | Auth architecture is wired (`SupabaseAuthProvider`, publishable key only). It activates when `DATA_MODE≠local_demo` and `PROVIYAA_API_BASE_URL` is set; MSG91/DLT are server-side. |
| 14 | Connectivity banner | The four Figma states are implemented in `ConnectivityBanner`/`ConnectivityBadge`. Only the non-nominal states (OFFLINE MODE ACTIVATED, SYNCING QUEUED TASKS, SYNC ERROR • RETRYING) overlay screens; the nominal ONLINE • HEARTBEAT ON state is shown by the Home online banner and the developer panel so it never covers screen content. |
| 15 | Home radar | The captured radar PNG had no transparency, so the pulse is drawn with Views (100 px translucent lime ring → 64 px #E8F8D5 ring → 24 px lime dot). |
| 16 | Multiply-blend overlays | The Figma intro-3 and location-permission frames composite a character with `mix-blend-mode: multiply`; the base illustrations already contain the character and React Native Web cannot blend, so the overlays are not rendered. |
| 17 | Web navigation handoff | On web, "Start navigation" opens Google Maps directions in a new tab; on Android/iOS it hands off to the navigation app on coordinates exactly as specified. |
| 18 | Offer screen param | `/offer/[id]` takes the job id (what push notifications and dispatch events carry); the screen also accepts an offer id. |
| 19 | Payouts (Cashfree) | Spec R11 deferred instant withdrawal until a payout provider was chosen; Cashfree Payouts was chosen. `/earnings/withdraw` has no Figma frame and follows the earnings / cash-in-hand visual language. The server decides every number (`GET /rider/wallet`); when it reports `instant.enabled = false` the app falls back to the weekly-only V1 behaviour. Withdrawals are blocked while cash in hand is above the city limit (same rule as going online) and for riders who are not approved. Payout accounts must be in the rider's name (poor name match refused, partial allowed). Profile and Withdraw open the payout screens with `?mode=manage` so an approved rider never re-submits the application. |
| 20 | Cash deposits (Cashfree PG) | The spec's deposit instructions mention a "OneLocal UPI collect request"; it is implemented with Cashfree Payment Links (checkout in the system browser via `expo-web-browser`) rather than the native Cashfree SDK, so it works in Expo Go and on web and adds no native module. UPI only by default (no card fees). The amount can't exceed the cash in hand. Status comes only from Cashfree (webhook → re-read, plus a sweep), never from the return URL. |
| 21 | KYC (Cashfree Secure ID) | The spec planned DigiLocker partner onboarding ("until then KYC is upload + manual review"); Cashfree Secure ID provides DigiLocker and the other checks now. Its DigiLocker API (2023-12-18) returns Aadhaar only, so PAN is verified by number with a name match against the Aadhaar name (one extra field on the KYC screen). The selfie is matched against the Aadhaar photo, which is kept encrypted until then (24 h at most). The driving licence uses the Aadhaar date of birth, asking for it only when Aadhaar isn't verified. Rented vehicles registered to someone else pass the RC check. |
| 22 | Splash film | The supplied 10 s film replaces the Figma lime splash. Riders open the app many times a day and resume deliveries from it, so the whole film plays once (first launch, Skip after 1 s) and later launches show only the 2.3 s logo reveal; reduced motion shows the static logo. The film is muted with `mixWithOthers` audio so it never interrupts music or navigation voice; its audio track was removed (4.3 MB → 1.4 MB MP4, 1.1 MB WebM for web, where open-source Chromium can't play H.264). The native launch screen uses the film's first-frame green and the supplied wordmark (cut out onto a square canvas so Android 12's circular icon mask doesn't clip it). The film's AI watermark (bottom-right ✦) is left as delivered. |
| 23 | Database schema | The spec's §6 schema is implemented as written, with the checks, indexes and columns the app already uses (e.g. `rider_code`, `tier`, `flags`, pickup-code hash, OTP lock). The spec's `rider_payout_methods` / `rider_payouts` are the existing Cashfree tables `payout_accounts` / `payouts` (keyed by `rider_id text`, amounts in paise) rather than a second copy. The 12-state engine is also enforced by a database trigger that mirrors the app's `TRANSITIONS` (a test keeps them equal) and owns `version`. Realtime goes through `rider_job_signals` (job id, state, version only) instead of exposing `delivery_jobs`, and a reassigned rider gets a `reassigned` update rather than a delete, because Supabase sends delete events to every subscriber. Master tables are created only when missing and otherwise left untouched. |
